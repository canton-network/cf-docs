<p><strong>Removed in 0.9.0.</strong> Historical definition from 0.8.4.</p>

Deprecated. Please use /v1/state/acs instead. Returns the ACS in creation date ascending order, paged, for a given migration id and record time.

<div class="x2mdx-ref-panel">
  <div class="x2mdx-ref-panel-head">
    <h3>Body</h3>

  </div>

<div class="x2mdx-ref-badges">

<div class="x2mdx-ref-fields">

  <div class="x2mdx-ref-field-row">
    <div class="x2mdx-ref-field-main">
      <code class="x2mdx-ref-field-name">migration_id</code>
      <span class="x2mdx-ref-type-badge">integer (int64)</span>

      <span class="x2mdx-ref-required-badge">required</span>

    </div>

    <div class="x2mdx-ref-field-description">The migration id for which to return the ACS.</div>

  </div>

  <div class="x2mdx-ref-field-row">
    <div class="x2mdx-ref-field-main">
      <code class="x2mdx-ref-field-name">record_time</code>
      <span class="x2mdx-ref-type-badge">string (date-time)</span>

      <span class="x2mdx-ref-required-badge">required</span>

    </div>

    <div class="x2mdx-ref-field-description">The timestamp at which the contract set was active. This needs to be an exact timestamp, i.e., needs to correspond to a timestamp reported by `/v0/state/acs/snapshot-timestamp` if `record_time_match` is set to `exact` (which is the default). If `record_time_match` is set to `at_or_before`, this can be any timestamp, and the most recent snapshot at or before the given `record_time` will be returned.</div>

  </div>

  <div class="x2mdx-ref-field-row">
    <div class="x2mdx-ref-field-main">
      <code class="x2mdx-ref-field-name">record_time_match</code>
      <span class="x2mdx-ref-type-badge">string</span>

    </div>

    <div class="x2mdx-ref-field-description">How to match the record_time. &quot;exact&quot; requires the record_time to match exactly. &quot;at_or_before&quot; finds the most recent snapshot at or before the given record_time.</div>

  </div>

  <div class="x2mdx-ref-field-row">
    <div class="x2mdx-ref-field-main">
      <code class="x2mdx-ref-field-name">after</code>
      <span class="x2mdx-ref-type-badge">integer (int64)</span>

    </div>

    <div class="x2mdx-ref-field-description">Pagination token for the next page of results. For this to be valid, this must be the `next_page_token` from a prior request with identical parameters aside from `after` and `page_size`; the response may be invalid otherwise.</div>

  </div>

  <div class="x2mdx-ref-field-row">
    <div class="x2mdx-ref-field-main">
      <code class="x2mdx-ref-field-name">page_size</code>
      <span class="x2mdx-ref-type-badge">integer (int32)</span>

      <span class="x2mdx-ref-required-badge">required</span>

    </div>

    <div class="x2mdx-ref-field-description">The maximum number of created events returned for this request.</div>

  </div>

  <div class="x2mdx-ref-field-row">
    <div class="x2mdx-ref-field-main">
      <code class="x2mdx-ref-field-name">party_ids</code>
      <span class="x2mdx-ref-type-badge">string[]</span>

    </div>

    <div class="x2mdx-ref-field-description">Filters the ACS by contracts in which these party IDs are stakeholders.</div>

  </div>

  <div class="x2mdx-ref-field-row">
    <div class="x2mdx-ref-field-main">
      <code class="x2mdx-ref-field-name">templates</code>
      <span class="x2mdx-ref-type-badge">string[]</span>

    </div>

    <div class="x2mdx-ref-field-description">Filters the ACS by contracts with these template IDs, specified as &quot;PACKAGE_NAME:MODULE_NAME:ENTITY_NAME&quot;.</div>

  </div>

</div>
